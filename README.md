# 💰 Битва за капитал — сессии и начисления

Веб-приложение для проведения игры: организатор создаёт сессию, участники
подключаются по коду и получают ID, а персонал с нескольких устройств начисляет
**деньги продавцам** и **очки полезности покупателям**.

## Что осталось в приложении

- Создание сессии с кодом, QR-кодом и ссылкой для участников.
- Подключение участников по коду и имени.
- Автоматическое распределение ролей: 60% покупателей / 40% продавцов.
- Экран участника с крупным **ID для начислений**.
- Две отдельные служебные страницы:
  - `/money` — **Деньги продавцам**;
  - `/points` — **Очки покупателям**.
- Ввод короткого ID участника (или полного) и суммы, мгновенное начисление.
- PIN для персонала — служебные страницы не открываются без него.
- Синхронизация между устройствами через Supabase Realtime + резервный опрос.
- Защита от потери начислений при одновременной работе с нескольких устройств.

Вся прежняя игровая логика (сделки, товары, таймеры, курсы валют, банк,
события, экран трансляции) удалена.

## 📖 Как провести игру

### 1. Организатор

1. Откройте `/host` (или нажмите «Панель организатора» на главной).
2. Создайте сессию.
3. Панель покажет:
   - **код сессии** для участников;
   - **PIN для персонала**;
   - QR-код и ссылку для подключения.
4. Передайте код участникам, а код и PIN — персоналу.

### 2. Участники

1. Откройте `/join` или ссылку вида `/#/join/ABC123`.
2. Введите имя.
3. На экране появится:
   - крупный **короткий ID** (8 символов);
   - полный UUID (можно скопировать);
   - роль: покупатель или продавец.
4. Покажите ID сотруднику. Начисления приходят автоматически.

### 3. Персонал

Откройте страницу механики на любом устройстве:

- `/money` — начисление денег продавцам;
- `/points` — начисление очков полезности покупателям.

Введите код сессии и PIN, затем:

1. Введите ID участника (короткий код или полный ID).
2. Введите сумму.
3. Нажмите «Начислить».

Страница сама проверит роль: деньги нельзя начислить покупателю, а очки —
продавцу. Список участников обновляется в реальном времени.

## 🆔 ID участника

Участник получает обычный UUID. Для ручного ввода на служебных страницах
показывается короткий код — первые 8 символов UUID, например `A1B2C3D4`.

Оператор может ввести:

- короткий код (`A1B2C3D4`);
- полный UUID (в том числе с дефисами).

Короткий код должен быть не короче 4 символов. Если у нескольких участников
совпадает начало ID, страница попросит ввести больше символов.

## 🔐 PIN для персонала

PIN генерируется при создании сессии (4 цифры) и хранится в
`sessions.admin_password`. Организатор видит PIN в своей панели и передаёт его
персоналу. Без PIN служебные страницы недоступны.

> PIN — это организационное ограничение, а не полноценная авторизация.
> Не публикуйте его участникам.

## 🗄 Supabase

Приложение использует две таблицы:

- `sessions` — сессии, код, статус, PIN;
- `players` — участники, роль, баланс, очки.

Схема: [`supabase-schema.sql`](supabase-schema.sql).

### Очки полезности: колонка или резервный режим

Приложение автоматически проверяет, есть ли в `players` колонка
`usefulness_points`:

- **если колонка есть** — очки пишутся в неё (и дублируются в
  `goods.__usefulness_points`);
- **если колонки нет** — очки пишутся в `goods.__usefulness_points`, и всё
  продолжает работать без миграции.

Чтобы включить отдельную колонку, выполните в Supabase SQL Editor:

[`migration-add-usefulness-points.sql`](migration-add-usefulness-points.sql)

Миграция также переносит уже начисленные очки из `goods` в колонку. После
применения приложение переключится автоматически.

### Переменные окружения

Создайте `.env`:

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

Без Supabase приложение работает в локальном режиме: сессия и начисления
доступны только на одном устройстве.

> ⚠️ В текущем `.env` используется ключ `service_role`. Его нельзя публиковать
> и отдавать в клиентский код. Для production создайте отдельный anon-ключ и
> настройте RLS-политики. Если ключ уже попал в репозиторий — перевыпустите его
> в Supabase.

## 🧠 Как устроена синхронизация

- Supabase Realtime подписывается на изменения `sessions` и `players`.
- Дополнительно раз в 4 секунды выполняется резервная синхронизация.
- Начисления используют оптимистическую блокировку: строка обновляется только
  если значение не изменилось с момента чтения. Поэтому два сотрудника,
  начисляющие одному участнику с разных устройств, не теряют начисления.
